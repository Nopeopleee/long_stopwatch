# 滴歲

把時間養成一隻會一直長大的碼表寵物。

滴歲是一個超輕量、可離線使用的 PWA。它不是讓計時器在背景持續執行，而是記住寵物的出生時間，在每次開啟時用目前時間重新計算已經陪伴了多久。

目前專案仍以純前端為主，核心目標是：**讓「一個可以跑很多年的碼表」逐漸變成真正有陪伴感、成長感與互動性的長期電子寵物。**

## 目前功能

### 長期計時

- 只保存出生時間 `startedAt`，不需要背景 timer 常駐。
- 關閉 App、重新開啟、手機重開機或暫時離線，都能依時間戳重新算出正確存活時間。
- 顯示天數與 `HH:MM:SS`，不受一般碼表 99 小時之類的上限影響。
- 寵物只能在按下「開始養」的當下出生，介面上不能手動指定或修改生日。
- 可替寵物改名字。
- 稱號會隨陪伴時間與里程碑成長。
- 首頁中央的滴歲本體會依年齡進入 6 個生命階段：新生滴、幼滴、成長滴、成熟滴、老朋友、傳說滴。
- 跨入新的生命階段時會播放一次成長演出；如果是在 App 關閉期間長大，下次回來也會補上最新階段的成長通知。

### 餵食與照顧

- 每隻已出生的滴歲會保存 `care.activatedAt`、`care.lastFedAt`、`care.feedCount` 與預留的 `care.diedAt`。
- 不需要背景 timer；每次開啟或回到前景時，直接用 `Date.now() - lastFedAt` 推導目前照顧狀態。
- 有效餵食有 **12 小時 cooldown**。太早按仍會有角色反應與提示，但不會刷新 `lastFedAt` 或增加餵食次數。
- 目前狀態節奏為：24 小時內健康、24～48 小時有點餓、48～72 小時飢餓、72～96 小時虛弱、4～6 天生病、6 天後危急。
- 第 7 天的「死亡」門檻已保留在規則模型裡，但 **目前尚未啟用真正死亡**；超過 7 天仍會停在危急，讓這一版先測試照顧節奏。
- 餵食成功會立即恢復健康，並播放 mascot 回饋動畫與輕震動。
- mascot 年齡階段與照顧狀態是兩條獨立軸；同一隻成熟滴可以是健康、飢餓或生病，不需要複製整套角色素材。
- 舊版已存在的寵物第一次載入照顧系統時會視同剛吃飽，從升級當下開始計算，不會因為過去沒有餵食紀錄而直接進入危急狀態。

### 里程碑與成長

目前共有 17 個里程碑，前期刻意安排得比較密集，讓剛開始養的幾個小時也有成就感：

| 時間 | 里程碑 |
| --- | --- |
| 1 小時 | 第一滴 |
| 6 小時 | 小小常駐 |
| 12 小時 | 半日相伴 |
| 1 天 | 第一天 |
| 3 天 | 三日同行 |
| 7 天 | 滿一週 |
| 14 天 | 兩週夥伴 |
| 30 天 | 滿月 |
| 50 天 | 五十日 |
| 100 天 | 百日紀念 |
| 180 天 | 半年相伴 |
| 365 天 | 一歲生日 |
| 500 天 | 五百日 |
| 730 天 | 兩週年 |
| 1,000 天 | 千日傳說 |
| 2,000 天 | 兩千日 |
| 3,650 天 | 十年神話 |

- 每個里程碑有自己的滴歲風格 SVG 成就圖示。
- 首頁預設只聚焦「最近解鎖」、「下一個目標」與目前階段進度，不再把 17 個項目全部攤開。
- 完整 17 個里程碑仍可在首頁用「查看全部」展開，想回顧完整旅程時再看。
- 會顯示目前解鎖數量、下一個目標、剩餘時間與階段進度。
- 里程碑剛解鎖時有短暫動畫與支援裝置上的輕震動回饋。
- App 關閉、切到背景或停留在其他頁面期間跨過里程碑時，下次回到首頁會顯示「旅程更新」解鎖浮層，不會只在列表裡默默變成已解鎖。
- 若離開期間一次跨過多個里程碑，會顯示最新一個里程碑並標示共解鎖幾個，同時讓相關成就圖示播放解鎖動畫。

### 分享成就卡

- 有滴歲出生後，首頁里程碑區會出現「分享」入口。
- 可即時產生 **1:1（1080×1080）** 貼文卡與 **9:16（1080×1920）** 限時動態卡。
- 卡片包含滴歲名稱、已陪伴天數與時間、目前稱號、最近里程碑、解鎖數量、出生日期，以及目前生命階段與照顧狀態對應的 mascot。
- 圖片使用 Canvas 2D 完全在本機產生，不需要上傳寵物資料到伺服器。
- 支援 Web Share API 的裝置可直接把 PNG 分享到其他 App；不支援時仍可下載 PNG。
- 分享卡會跟隨目前淺色 / 深色布景，維持滴歲的水滴、漣漪與低彩度視覺語言。

### PWA / 離線

- 可在支援 PWA 的瀏覽器安裝成獨立 App。
- Service Worker 提供離線使用能力。
- App 重新回到前景時會重新讀取狀態與更新畫面。
- HTML 導航使用 **network-first**，優先取得最新版頁面，離線時再回退快取。
- 帶版本號的 CSS / JavaScript 使用 **cache-first**；版本變更時由新的 URL 自然失效，避免每次啟動都等待網路。
- icon、manifest、SVG 等其他同源靜態資源使用 **stale-while-revalidate**，先快速顯示快取，再於背景更新。
- Service Worker cache 目前為 `disui-v19`。

### 效能與可及性

- 主計時區使用 `role="timer"` 並關閉即時播報，秒數每秒變動不會持續打斷螢幕閱讀器。
- 重要事件（例如出生、改名、當下解鎖里程碑，以及回來後補上的離線期間解鎖）透過獨立的 polite live region 播報。
- 完整里程碑清單使用可存取的展開按鈕與 `aria-expanded`，預設收合以降低首頁資訊密度。
- 計時畫面已拆分更新週期：
  - `HH:MM:SS` 與天數：每秒只更新必要數字。
  - 里程碑剩餘時間與進度：每分鐘更新。
  - 稱號與里程碑解鎖狀態：跨越門檻時立即更新。
  - 名稱、出生時間、按鈕與其他靜態狀態：只有資料變更或頁面重新回前景時才更新。
- `Intl.DateTimeFormat` 只建立一次，不再每秒重建 formatter。
- 頁面進入背景時會停止 UI 計時更新器；回到前景後直接依 `Date.now() - startedAt` 重算，因此不會少算時間，也能減少無效工作。

### 外觀與設定

- 深色、淺色、跟隨裝置三種布景模式。
- 主頁採用水滴、漣漪與時間成長作為主要視覺語言。
- 獨立設定頁，不把備份、主題、安裝與危險操作全部塞在主畫面。
- 支援 `prefers-reduced-motion`，使用者要求減少動畫時會降低或停用非必要動效。

### 資料與備份

- 核心資料目前儲存在 `localStorage`，key 為 `long-stopwatch-v1`。
- 已看過的里程碑進度另外保存在 `dipai-last-seen-milestone-v1`，並綁定該隻滴歲的 `startedAt`，避免重置、匯入或換新寵物後誤判成舊里程碑。
- 品牌雖已改名為「滴歲」，既有的 `dipai-*` localStorage key 暫時保留作為相容層，避免更新後讓既有寵物、主題或里程碑紀錄消失。
- JSON 備份格式已升到 **version 2**，會一起保存名稱、出生時間與照顧資料。
- 匯入仍相容舊版 version 1 / 舊 raw state；缺少 care 的舊備份會從匯入當下開始新的照顧計時。
- 未出生的備份（`startedAt: null`）也可正常匯入。
- 重置需要長按 2 秒，避免誤觸。

> 清除瀏覽器網站資料、PWA 儲存空間或解除安裝時，仍有可能刪除本機資料。要長期養幾年甚至十年，現階段仍建議偶爾匯出備份。

## 計時原理

核心其實很單純：

```js
Date.now() - startedAt
```

滴歲沒有真的讓一個 JavaScript timer 在背景跑幾年。`startedAt` 是出生時間；畫面上的存活時間只是每次用現在時間重新計算。

這也代表關 App、瀏覽器暫停背景頁面、手機重開機，都不會讓碼表本身「少算一段時間」。

## 產品方向

現在的滴歲已經不只想做成「漂亮的長期碼表」。下一階段會把重點放在 **照顧、陪伴、成長與長期保存**，讓使用者真的有「我養了一隻東西」的感覺。

### 核心玩法：餵食、健康與死亡

第一階段照顧系統已經上線：首頁原本單純的「存活中」會改成真正的健康狀態，並提供餵食互動。

目前採低壓節奏：

```text
健康 → 有點餓 → 飢餓 → 虛弱 → 生病 → 危急 →（死亡門檻暫未啟用）
```

有效餵食最短間隔為 12 小時；忘記一天不會出事，真的長時間完全不照顧才會逐步惡化。現階段先把死亡鎖住，用實際使用感受確認節奏是否合理，再決定永久死亡、救回機制、假期模式與治療玩法。

這套照顧狀態已經和 mascot 視覺、分享卡、備份資料與前景重新計算串在一起；未來導入 Web Push 與後端時，可以沿用同一組時間規則。

## Roadmap## Roadmap

以下為目前規劃，**不代表已經完成或承諾特定版本上線**。已完成項目會保留在 Roadmap 中，方便追蹤設計決策。

### 1. ✅ 計時與可及性細節

已完成第一輪改善：主計時區不再使用會跟著秒數持續播報的 live region，而是採 `role="timer"` / `aria-live="off"`。重要事件改由獨立 polite live region 播報，避免螢幕閱讀器每秒被打斷。

### 2. ✅ 拆分 render 與降低長期耗電

已把原本每秒完整 render 拆成不同更新層級：

- 秒數與主要時間：每秒更新。
- 里程碑倒數與進度：每分鐘更新。
- 稱號與里程碑狀態：跨門檻時更新。
- 姓名、生日、按鈕等靜態資料：只有狀態改變時更新。
- 頁面進入背景後停止 UI timers，回前景再依時間戳重算。
- 日期 formatter 改為重用單一實例。

### 3. ✅ 補上「離線期間解鎖」體驗

已完成第一版：

- 額外保存「這隻滴歲最後看過的里程碑數量」，並與 `startedAt` 綁定。
- App 回到前景或重新開啟時，會用目前實際經過時間重新計算里程碑，再和最後看過的進度比較。
- 若離開期間有新里程碑，首頁會顯示不打斷操作的「旅程更新」浮層，帶出最新里程碑圖示、名稱與本次總解鎖數量。
- 同時會補播相關成就圖示的解鎖動畫、輕震動與螢幕閱讀器播報。
- 顯示後立即記錄為已看過，避免重新整理或重開 App 後重複彈出。
- 第一次升級到這套機制時，會把當前進度直接設成基準，不會把過去已經完成的十幾個里程碑一次全部重播。

### 4. ✅ 收斂首頁里程碑資訊

已完成第一版首頁收斂：

- 首頁預設只顯示「最近解鎖」與「下一個目標」兩張旅程摘要卡。
- 保留目前解鎖數量與當前階段進度條，讓成長方向一眼可讀。
- 17 個完整里程碑改成預設收合的「完整旅程」，需要時再用按鈕展開。
- 展開控制使用 `aria-expanded` / `aria-controls`，鍵盤與輔助技術都能理解目前狀態。
- 沒有刪掉任何里程碑資料或解鎖動畫；這次只改資訊架構，讓首頁不再被長清單淹沒。

### 5. ✅ 改善 Service Worker 快取策略

已依資源類型拆分策略：

- HTML / navigation：**network-first**，優先取得最新版，離線時回退快取頁面。
- 版本化 CSS / JavaScript：**cache-first**，版本 URL 不變時直接從快取啟動，新版本則使用新的 URL。
- 其他同源靜態資源：**stale-while-revalidate**，先讀快取並在背景更新。

這樣保留先前為避免「HTML 新、JS 舊」所做的安全性，同時減少每次開啟 PWA 都必須等待所有靜態資源走網路的成本。

### 6. ✅ 滴歲的生命階段 / Mascot 成長

已完成第一版 6 階段成長系統：

| 時間 | 生命階段 |
| --- | --- |
| 出生～1 天 | 新生滴 |
| 1～7 天 | 幼滴 |
| 7～30 天 | 成長滴 |
| 30～365 天 | 成熟滴 |
| 365～1,000 天 | 老朋友 |
| 1,000 天以上 | 傳說滴 |

- 原本首頁中央只有抽象水滴，現在會直接顯示真正的滴歲 mascot；主視覺採 mascot 與計時資訊左右分欄，不再把天數疊在角色上。角色區再放大一級，讓寵物本身有足夠存在感，同時保留時間為主要資訊層級。
- 6 階段使用同一角色的漸進式 SVG 設計：身體逐漸飽滿、出現手部與核心、水紋環、陪伴印記，最後進入帶星點與發光感的傳說型態。
- 生命階段只由陪伴時間決定；未來的飢餓 / 健康 / 生病會作為第二條狀態軸疊加，不需要做「6 階段 × N 健康狀態」的大量重複素材。
- 跨階段時會有水紋、發光與新造型浮現的成長演出，並支援輕震動與輔助技術播報。
- `dipai-last-seen-life-stage-v1` 會把最後看過的生命階段和 `startedAt` 綁定；關 App 期間長大，下次回來仍會補播最新階段。
- 第一次升級到生命階段功能時，以目前階段當作基準，不會突然把過去所有成長演出補播一輪。
- `prefers-reduced-motion` 會關閉非必要的漂浮、水紋與進化動畫。

### 7. ✅ 分享成就卡

已完成第一版純前端分享卡：

- 提供 1:1（1080×1080）與 9:16（1080×1920）兩種社群尺寸。
- 以 Canvas 2D 在本機即時繪製，不需要後端，也不會把寵物資料送出去。
- 卡片會帶入滴歲名稱、存活時間、稱號、最近里程碑、里程碑數量、出生日期，以及依目前年齡對應的實際 mascot / 生命階段。
- 視覺延續主頁的水滴、漣漪、低彩度漸層，並依目前淺色 / 深色主題產生對應版本。
- 支援 Web Share API / Files 的瀏覽器可直接分享 PNG；其餘瀏覽器提供下載 PNG fallback。
- 分享介面提供即時預覽與尺寸切換，沒有改動既有滴歲存檔格式。

### 8. 備份健康度與更可靠的資料保存

先在純前端階段增加：

- 顯示上次匯出備份時間。
- 很久沒備份時才柔性提醒。
- 規劃 IndexedDB / localStorage 的本機冗餘。

未來導入後端後，再加入真正的跨裝置同步與雲端備份。

### 9. 里程碑與照顧通知

通知應該低頻且有價值，不做每天轟炸式提醒。

可能包含：

- 即將需要餵食。
- 已進入飢餓 / 生病狀態。
- 30 天、100 天、一歲等重要里程碑。
- 久違回來時的狀態摘要。

App 關閉後仍可靠推播，預計搭配未來的後端與 Web Push 實作。

### 10. 好友、群組與排行榜

後端成熟後再考慮社交功能：

- 邀請朋友加入同一個群組。
- 比誰養得最久。
- 顯示好友目前的稱號、生命階段與健康狀態。
- 排名以伺服器可信時間為準，而不是直接相信客戶端系統時間。

社交功能不會優先於單人養成體驗；首先要讓一個人養滴歲本身就夠有趣。

### 11. 🚧 餵食 / 健康 / 生病 / 死亡系統

第一階段已完成：

- 新增 `care` 資料，核心以 `lastFedAt` 推導狀態，不需要背景常駐。
- 12 小時有效餵食 cooldown；提早按只會得到「還很飽」的互動回饋。
- 已實作健康、有點餓、飢餓、虛弱、生病、危急六個可進入狀態，並保留第 7 天死亡門檻。
- 首頁狀態標籤與照顧提示會跟著實際狀態更新。
- mascot 會依照照顧狀態改變飽和度、亮度、姿態與動效；餵食成功也有獨立回饋。
- 已有寵物採 migration grace：第一次升級不追溯過去未餵食時間。
- 備份升級為 version 2，同時相容 version 1。
- 分享卡會帶入目前照顧狀態，並對 mascot 套用相應視覺。
- 頁面回到前景時會重新從時間戳推導狀態。

尚未啟用：

- 真正死亡與 `diedAt` 寫入。
- 復活 / 治療規則。
- 假期或旅行寬限。
- 關閉 App 後的 Web Push 照顧提醒。

先以現在這版實際養一段時間，再決定死亡要多嚴格，避免規則一上線就把長期寵物變成懲罰型打卡。

## 未來後端方向## 未來後端方向

如果需要雲端同步、可信出生時間、排行榜、好友與可靠 Web Push，預計把目前純靜態架構逐步移到 Cloudflare 生態：

- **Workers + Static Assets**：同一部署提供前端與 API。
- **D1**：寵物、群組、餵食紀錄、健康狀態等結構化資料。
- **Cron / 排程能力**：計算照顧狀態與需要發出的提醒。
- **Web Push**：在 PWA 關閉時送出重要通知。

真正需要公平性的功能（例如排行、出生時間、死亡時間）最終應以伺服器時間為準，而不是完全信任客戶端時間。

## 本機開發

Service Worker 需要 HTTPS 或 localhost。

```bash
npx serve .
```

或：

```bash
python -m http.server 8080
```

然後開啟：

```text
http://localhost:8080
```

- Web App Manifest

## 資料可信度說明

目前出生時間雖然不能從 UI 手動修改，但專案仍是純前端：

- 使用者可以透過開發者工具修改 `localStorage`。
- 匯入 JSON 備份本身也能帶入出生時間。
- 因此目前的「公平性」主要是產品介面的約束，不是防作弊機制。

若未來加入公開排行榜，會改由伺服器產生並保存可信的出生時間與其他關鍵生命事件。
